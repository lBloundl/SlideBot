# ДЗ-7. OKR, MVP, запуск

**Проект:** SlideBot

## 1. OKR на квартал

### Цель

**Специалист может подготовить проверяемый черновик отчёта о статусе проекта из своих рабочих материалов и использовать его для регулярной отчётности.**

### Ключевые результаты

На момент начала разработки действующего продукта нет, поэтому базовые значения равны нулю. Целевые значения — план пилотного запуска, а не уже достигнутые показатели.

| Ключевой результат | Метрика из дерева | Было | Должно стать |
|---|---|---:|---:|
| Не менее 5 из 8 участников пилота получают первый редактируемый PPTX после загрузки материалов | Активация: доля пользователей, получивших первый результат | 0 | 5 из 8 |
| Не менее 3 из 5 участников используют хотя бы 3 слайда из черновика в своей отчётной работе, затрачивая не более 20 минут на проверку и исправление | Использование результата и время до готового черновика | 0 | 3 из 5 |
| Не менее 2 участников возвращаются за вторым отчётом в течение 30 дней | Повторное использование | 0 | 2 участника |

Дополнительно устанавливаем технический показатель качества: в тестовых отчётах ключевые факты должны быть подтверждены исходными материалами либо явно помечены как требующие проверки. Неподтверждённые даты и показатели нельзя выдавать за достоверные сведения.

## 2. Спецификация MVP

### Какое допущение из ДЗ-6 проверяет

Специалисты, которые регулярно готовят статус-отчёты, готовы предоставить обезличенные материалы, получить из них черновик презентации и использовать результат после проверки.

Это главное допущение: если черновик не помогает выполнять работу, дальнейшее расширение продукта не имеет смысла.

### Что должно произойти, чтобы считать допущение подтверждённым

В пилоте участвуют 5 человек из целевого сегмента.

Гипотеза получает предварительную поддержку, если:

- не менее 3 участников используют хотя бы 3 слайда из готового отчёта;
- эти участники считают проверку и исправление результата приемлемыми по времени;
- не менее 2 участников хотят повторить процесс при подготовке следующего отчёта.

Дополнительно вручную проверяем, что информация в слайдах соответствует предоставленным материалам. Это небольшой пилот, поэтому его результат нельзя автоматически переносить на весь рынок.

### Что входит в MVP

1. Telegram-бот, который принимает от пользователя от 1 до 3 файлов.
2. Поддержка только простых форматов: `.docx`, `.xlsx`, `.txt` и `.csv`.
3. Ограничение размера файла, например до 5 МБ.
4. Извлечение текста из файлов с помощью готовых библиотек Python.
5. Передача извлечённого текста в AI-модель для выделения:
   - общего статуса проекта;
   - выполненных результатов;
   - ближайшего плана;
   - проблем и рисков;
   - следующих шагов.
6. Генерация одного PowerPoint-файла `.pptx` по заранее подготовленному шаблону из 5 слайдов.
7. Пометка отсутствующих или сомнительных данных надписью «ПРОВЕРИТЬ», а не самостоятельное придумывание значений.
8. Отправка готового файла пользователю в Telegram.
9. Удаление исходных файлов после обработки.

**Важно:** презентация является черновиком. Перед отправкой руководителю или команде пользователь должен самостоятельно проверить содержание.

### Что сознательно не входит

- распознавание сканов и изображений;
- поддержка PDF в первой версии;
- подключение Google Drive, CRM и корпоративных систем;
- автоматическая сверка всех противоречий между источниками;
- несколько вариантов дизайна и индивидуальный фирменный стиль;
- совместное редактирование и личный кабинет;
- корпоративные роли и права доступа;
- сложная история всех проектов пользователя;
- встроенная оплата и автоматическая подписка;
- создание презентаций на любые темы.

Такое ограничение позволит сделать первую версию без большой команды и бюджета.

## 3. Роли агентов

Для разработки можно разделить работу на три роли. Это не означает, что нужно нанимать трёх человек: на учебном проекте один автор может выполнять их последовательно, используя AI-помощника для отдельных задач.

| Роль | Что делает | Критерий приёмки |
|---|---|---|
| Исследователь / аналитик | Извлекает факты из материалов, выделяет результаты, проблемы, сроки и следующие шаги, формирует структурированный результат для презентации | В тестовом наборе основные сведения распределены по нужным разделам, а отсутствующие данные помечены для проверки |
| Разработчик | Создаёт Telegram-бота, загрузку файлов, обращение к AI API и генерацию PPTX по шаблону | Бот принимает поддерживаемые файлы, формирует презентацию, отправляет её пользователю, а неподдерживаемые файлы отклоняет с понятным сообщением |
| Проверяющий / редактор | Сверяет готовую презентацию с исходными материалами, проверяет структуру и корректность фактов | Файл открывается, ключевые факты подтверждены источником или помечены, нет неподтверждённых дат и показателей, представленных как факт |

## 4. Правила проекта для агентов

### Стек и версии

- Python 3.11 или выше.
- aiogram 3.x для Telegram-бота.
- python-docx для чтения DOCX.
- openpyxl для чтения XLSX.
- python-pptx для создания презентаций.
- Готовая языковая модель через API.
- Переменные окружения для хранения API-ключей и токенов бота.
- Git для хранения кода и истории изменений.

На первой версии не нужна сложная база данных. Временные файлы хранятся только на время обработки и удаляются после завершения операции.

### Что нельзя трогать

- Нельзя помещать API-ключи и токены в исходный код или публичный репозиторий.
- Нельзя отправлять в тесты реальные конфиденциальные документы.
- Нельзя менять структуру итоговой презентации без согласования.
- Нельзя автоматически считать отсутствующие данные нулевыми или придумывать сроки.
- Нельзя удалять уже работающие функции без проверки.
- Нельзя добавлять новые библиотеки и сервисы без объяснения, зачем они нужны.

### Как оформлять результат

- Код разделён на понятные части: Telegram-бот, чтение файлов, обработка AI и генерация PPTX.
- Для запуска есть README с пошаговой инструкцией.
- Есть файл `.env.example` без настоящих ключей.
- Есть несколько тестовых файлов с вымышленными данными.
- После каждой задачи указывается, что изменено и как это проверить.

### Что делать при сомнении

Если формат файла не поддерживается, данных недостаточно или источники противоречат друг другу, система должна сообщить об этом и попросить пользователя проверить информацию. Нельзя самостоятельно выбирать сомнительный вариант и выдавать его за достоверный.

## 5. Задачи для агентов

### Задача 1. Обработка файлов и подготовка содержания отчёта

- **Контекст:** SlideBot получает документы, таблицы и заметки менеджера проекта. Его задача — подготовить структурированное содержание для черновика статус-отчёта. Эта задача является первой частью MVP.
- **Что сделать:** реализовать приём 1–3 поддерживаемых файлов, извлечение текста из DOCX, XLSX, TXT и CSV и передачу содержания в AI-модель. На выходе должен формироваться структурированный результат с общим статусом, результатами, планом, проблемами и следующими шагами. Неизвестные сведения должны помечаться для проверки.
- **Ограничения:** не использовать OCR, не подключать сторонние корпоративные хранилища, не добавлять PDF и сканы. Не сохранять исходные файлы после завершения обработки. Не использовать реальные конфиденциальные материалы.
- **Критерии приёмки:** бот принимает поддерживаемые файлы; может извлечь текст; формирует пять требуемых разделов; при отсутствии информации указывает, что её нужно проверить; при неподдерживаемом формате показывает понятную ошибку.

### Задача 2. Создание и проверка PowerPoint

- **Контекст:** после анализа материалов SlideBot должен вернуть пользователю редактируемый отчёт в формате PowerPoint. Это основной результат, который пользователь оценивает.
- **Что сделать:** создать один простой шаблон `.pptx` из пяти слайдов: общий статус, результаты, план, проблемы и риски, следующие шаги. Заполнять его структурированным содержанием, сохранять файл и отправлять пользователю в Telegram.
- **Ограничения:** не создавать уникальный дизайн для каждого пользователя, не добавлять сложную анимацию, графики и изображения, если для них нет надёжных данных. Не выдавать черновик за окончательный проверенный отчёт.
- **Критерии приёмки:** PPTX открывается в PowerPoint или совместимой программе; информация расположена на нужных слайдах; текст не выходит за пределы основных блоков; неподтверждённые значения отмечены; пользователь получает файл обратно в Telegram.

## 6. План запуска

### Первые пользователи

Первые участники — 5 специалистов, которые самостоятельно и регулярно готовят статус-отчёты по проектам.

Их нужно найти через:
- личные знакомства и рекомендации преподавателей или знакомых;
- тематические Telegram-сообщества по управлению проектами;
- профессиональные контакты и публикации в LinkedIn.

Не стоит считать одногруппников целевыми пользователями, если они не выполняют такую работу регулярно. Они могут помочь протестировать интерфейс, но это не заменяет проверку на выбранном сегменте.

### Через какой канал придут

Основной канал — личные рекомендации и тематические Telegram-сообщества. Это бесплатно и подходит для небольшого учебного проекта.

Пользователю предлагается бесплатная проверка одного черновика на обезличенных материалах. Никакой платной рекламы для первого запуска не требуется.

### Критерий успешности запуска

В течение первого месяца:

- 5 представителей целевого сегмента попробовали продукт;
- минимум 3 использовали не менее 3 слайдов из полученного черновика;
- минимум 2 захотели повторить подготовку отчёта;
- при ручной проверке не обнаружено неподтверждённых дат и показателей, представленных как достоверные.

Дополнительно можно спросить пользователей, готовы ли они платить за ограниченную подписку около 199 ₽ в месяц. Ответы фиксируются как интерес к цене, а не как реальные продажи.

### Что делаем, если не вышло

Если пользователи не загружают материалы, выяснить, что мешает: неудобный формат, недоверие к передаче документов или отсутствие необходимости в таком инструменте.

Если они получают PPTX, но не используют слайды, выяснить, что именно не подходит: содержание, точность, структура или оформление.

Если пользователи довольны первым результатом, но не возвращаются, проверить, действительно ли работа выполняется регулярно и подходит ли подписная модель.

Вместо добавления новых функций нужно исправить главную проблему, провести ещё один небольшой тест и только потом решать, стоит ли расширять продукт.

## Итог

В первой версии SlideBot — небольшой Telegram-бот с ограниченными возможностями, а не полноценная платформа для автоматизации проектного управления.

Основная задача — проверить, готов ли человек использовать черновик статус-презентации, созданный из его материалов, и возвращаться к этому процессу. Для этого достаточно одного шаблона, нескольких форматов файлов, готовой AI-модели и ручной проверки результатов.

Такой MVP можно собрать самостоятельно, без найма команды, платной рекламы и больших первоначальных расходов.
